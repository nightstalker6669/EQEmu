# Automatic matched runtime releases

The Build workflow compiles and runs the existing tests for Linux x86-64 and Windows x64. Only a successful push to this repository's `develop` branch also packages and uploads runtime artifacts. A release job needs both platform jobs to succeed. PRs and other branches never publish; build jobs have read-only repository permissions, and only the serialized release job has job-scoped `contents: write` via `GITHUB_TOKEN`/`gh`.

`release-inputs.json` commits exact public asset URLs, lengths and SHA256 values for sanitized database content and curated runtime scripts/opcodes/templates/licenses. The database owner's contract pins SQL, all 331 Housing JSON files and qualification documents. No live database or dirty developer checkout supplies release content. Only allowlisted portable seed content is reused; native binaries, recovery helper and client export tool come from the same platform's current checkout/build. To update content, commit a separately owner-reviewed sanitized immutable input and its exact hashes. Never select a mutable Latest input.

`package_runtime.py` checks source ancestry/commit, input hashes, database member hashes/inventory, architecture, binary hashes, Windows DLL closure and Linux OS/Perl ABI requirements. It strips debug information from staged Linux copies only, excludes source/build/cache/log/debug bulk, retains dependency notices, and writes stable ZIP names, install guides, manifests and checksums. External licensed resources and operating system/Perl prerequisites are documented. Neither packaging nor publishing deploys a serving process, imports SQL or changes Desktop packages.

`publish_release.py` binds both platform artifacts to the current run/attempt/commit and identical database inputs. It stages a unique versioned draft, uploads all files, verifies remote asset sizes/SHA256 digests, and publishes with `make_latest` only after the complete set is verified. Failure before publication preserves the previous good Latest. Old releases are retained. The release job is serialized; source-head and recorded run-number guards also prevent a stale finishing run from promoting over newer source/Latest. A superseded build may leave an unpublished draft. A failed attempt is not retried blindly; diagnose the concrete error, then use a new source commit or an explicitly chosen Actions rerun. Each attempt gets its own tag.

Stable URLs are `/releases/latest/download/EQEmu-RoF2-Linux-x86_64.zip` and `/releases/latest/download/EQEmu-RoF2-Windows-x64.zip`. Each platform has `.zip.sha256`, `.manifest.json` and `.INSTALL.md` companions; `RELEASE-INPUTS.json` and `SHA256SUMS` cover the complete release. Exact source and pinned submodules remain available at the recorded repository commit. Full SQL is new-empty-database only; native gameplay acceptance and unresolved reconstruction limitations remain separate from CI success.

Local validation is syntax/structure only. The first actual two-platform CI run and automatic release are the end-to-end validation; do not claim release success until the Latest readback and both jobs succeed.
