mysql_migration.py is the concrete manual MySQL helper. Its default invocation only prints the source plan and makes no connection. Manual --apply is solely for the coordinated window after the current custody check; it takes the existing owner evidence file, server configuration and private backup directory. It verifies the target database, item/destination preimages, active copies/references and target reward rows, then performs13bound DML statements in one transaction. A durable exclusive prepared backup precedes the first write. Exact full postimages and affected-row counts are checked before commit; failure rolls back without retry. If commit succeeds but writing the completion receipt fails, it explicitly reports that state and preserves the prepared backup for inspection.

The helper never changes player inventory, GUIDs, recovery payloads or terminal receipts. A matching active copy/reference stops it. --reverse requires the matching committed forward receipt and prepared backup, unchanged postimages, no current copies or native reward selections/claims, and the coordinated custody/window check. It reverses only the definition/reward writes. Any earned/native copy or claim stops reversal; it does not restore stale player snapshots.

The current source payload stays outside installer registration. Manual --apply is explicit operator intent; its old research-stage flags do not automatically activate it. Do not run it while the52current canonical rows/session handoff is unresolved or another owner controls the shared runtime. The existing owner evidence is used and hashed; this is not a new approval-document framework.
