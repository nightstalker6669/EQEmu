Native instance respawn state and its 86400-second timer prevent an ordinary opened chest respawn during the six-hour instance. Condition setter/getter behavior does not prove a durable commit. No runtime journal or completed-history regrant is introduced.

The task template creates a Mission, while inspected eq.get_expedition accessors require Expedition. Raw eq.update_instance_timer does not synchronize every dynamic-zone lifecycle cache, so neither path is used as a guessed Mission timer API. The selected window is at most 600 seconds for the chest NPC/corpse, bounded by normal native instance expiry and port-out. It is not an early whole-instance expiry implementation. Zone restart can lose the original local deadline and phases; no crash-atomic persistence or native acceptance is claimed. These are explicit deployment/acceptance limitations, not reasons to silently invent another reward engine.
