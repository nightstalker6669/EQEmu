This isolated source implements the inventory owner's exact `OnOriginalNativeUsePublished(Client&,PublishedNativeUse&)` boundary. `Take(actual_owner)` is the first operation; failed or duplicate consumption returns before queries, allocation or effects. The receipt header is copied byte-for-byte from the owner's pinned interface. Its constructor remains private to NativeItemCustody. No sink caller, writer, receipt factory, Lua entry, packet interface, timer or recovery path is registered here.

The receiver reads the actual native current quest slot, checks bounds before the existing getter, and revalidates the same accepted occurrence, original caster, original world/instance and finite rule/consumer. It preserves the genuine original-use frame and native click sequence. The combine branch accepts only the original A and matching inactive output identity supplied by the writer; it neither regrants the output nor creates a construct, advances goal2, saves or assigns a task. Published cursor placement and canonical charges come from that same receipt; output quantity does not imply a hardcoded charge count or cursor-top location.

The activation source retains its original attempt in a private Client-owned unique_ptr before native NPC creation. It uses the real native cached NPC definition, constructor, loot and AddNPC path, with the original producer's pre-callback registration capture. It never invokes the old boolean-only charge entry: the replacement producer header removes both ActualOriginalActivationCharge and CreateActualOriginalConstructOnce. The same original use comes exclusively from the consumed writer receipt. No client/actor/attempt is dereferenced after mutable AddNPC callbacks.

Activation remains unreachable: original placement is empty/selectedfalse and actor lifetime/no-same-frame reuse is explicitly unselected. Task169 is additionally held for its real personal participant cohort. Client ownership alone does not prove an NPC cannot outlive its owner, so it does not lift that lifetime hold. Initial167 acceptance and native death routing also remain held. A consumed receipt followed by any downstream hold does not authorize a refund, regrant, spawn retry or reconstruction.

This delta composes Client source against the reviewed World/activity batch, without changing that batch or its current build. It additionally depends on the earlier original producer's entity.cpp pre-spawn capture and task_client_state.cpp same-save observation, plus its item-use/construct-identity headers. Those source dependencies are not silently installed by this patch. The actual staged inventory writer and issuing callsite remain with their owner. This is an unregistered source implementation, not an inventory implementation or native acceptance result. No shared checkout, runtime, SQL, client, build or test action was performed.
