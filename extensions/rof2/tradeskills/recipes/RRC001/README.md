`apply.sql` is a manually applied MariaDB10.11 script for a dedicated, transaction-free admin connection. It requires strict mode and InnoDB foundations, checks item identities/container dependencies, rejects partial batches and recipe ID/name/result collisions, inserts only when the entire batch is absent, accepts only an exact full reapply, verifies logical rows and pre/post count deltas, and rolls back on error. Temporary staging tables disappear with the session; no permanent helper procedure, updater registry or schema version is added. Stop the client on any SQL error. Recipe/content writers must be coordinated and quiescent; this is not a global concurrency proof.

`rollback.sql` requires the exact complete installed postimage and refuses if learned recipe references exist. It removes only this batch. It does not rewind auto-increment values or undo player crafts/derived items; rollback requires a separately coordinated preconditions review.

Validation so far: read-only content inventory, exact source fact extraction and static dependency/collision/quantity checks. Neither SQL script has been executed or rehearsed on MariaDB.
