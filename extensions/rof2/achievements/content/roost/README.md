# Blackfeather Roost quests, acquisition and destructible nests

This milestone adds **15 quests, 54 activities and five May 2013 achievement definitions**, with eight task reward sets and three historically confirmed parent jewellery reward sets. It includes two Griffon Treat recipes, five feather groundspawns, five Royal Trinket placeholder repairs, seven original nest NPC model repairs and 82 exact original static-actor bindings. Original NPC stats, spawn locations and respawn timers are preserved.

The historical cutoff is **May 31, 2013**. [Quest mechanics and dated sources](provenance/quests.json), [confirmed rewards](provenance/parent-rewards.json), [unresolved armour](provenance/unresolved-armour.json), [defaults and limits](provenance/defaults-and-limits.json) and [engine scope](provenance/engine.json) distinguish period evidence, native identity checks and emulator reconstruction.

Ascending's two Intricate Consigned wrists have unresolved exact choices/selection rules. Raider's generic glove plus cloak/range bundles have unresolved exact glove choices and class mapping. **Neither parent reward set is installed or enabled.** The three confirmed sets preserve both earrings or both rings in each class-appropriate option where the period source lists both. Later Conjurer jewellery is excluded. Do not interpret achievement completion as a promise that these two missing armour claims are implemented.

## Installation order

Use this branch's integrated achievement engine and required schema migrations: content, state and reward-class migrations in the [main installation guide](../../../../../docs/rof2/INSTALL.md). Complete earlier reviewed packages, including Crescent, Blightfire and Mesa, first; the scripts reuse `achievement_quest_mesa_inventory` and `achievement_quest_blightfire`. The Roost engine source is integrated directly; do not reapply an archived patch. Rebuild all Map/BVH-header consumers and deploy matching world/zone binaries before reconnecting players. No new opcode, packet layout or database schema migration is introduced here.

Back up database, quests and binaries together, disconnect players and stop game services, leaving MariaDB available. Python3 and MariaDB client/dump utilities are required. Use a protected client options file and adapt all paths/database names. From this directory, Linux example:

```sh
python3 install.py --mysql-command-json '["mariadb","--defaults-extra-file=/private/eq.cnf","peq"]' --quests /path/to/server/quests

python3 install.py --mysql-command-json '["mariadb","--defaults-extra-file=/private/eq.cnf","peq"]' --dump-command-json '["mariadb-dump","--defaults-extra-file=/private/eq.cnf","peq"]' --quests /path/to/server/quests --backup /path/to/backups/roost --apply --enable-reviewed
```

The default invocation is read-only. `--apply` backs up affected content tables and quest files, then imports base SQL in one client session and installs/composes scripts. **Without `--enable-reviewed`, base tasks/recipes/rewards/catalogue remain disabled.** `--enable-reviewed` additionally runs the final guarded activation for the 15 known tasks, five definitions, eight task sets and three confirmed parent sets; it cannot enable the two absent armour sets. Native quest completion, nest destruction/credit/retention/respawn, feather acquisition/handins/reward delivery and paired parent reward persistence passed on the corresponding develop-based combined server. See [native coverage and remaining limits](provenance/native-status.json).

For native Windows use `py -3 install.py`, native MariaDB executable paths and `C:/EQEmu/...` paths in the same argument arrays; no WSL is required. Native Windows execution has not been verified for this milestone. For Akk-stack run the host Python installer from the stack directory with the absolute installer path; replace the client arrays with e.g. `["docker","compose","exec","-T","mariadb","mariadb","--defaults-extra-file=/private/eq.cnf","peq"]` and the corresponding `mariadb-dump` array. The options file must exist inside that database container; `--quests` targets the host-mounted quest directory.

SQL order is `01_catalogue`, `02_acquisition`, `03_tasks`, `04_parent-rewards`, `05_nests`, then optional `06_activation`. All review variables are scoped to the installer client session. Catalogue imports do not depend on a private development catalogue. Guards reject conflicting native identities, ownership or existing content. Unknown custom NPC callbacks, alternate named/Perl routes and modified hooks require deliberate composition; the installer does not silently overwrite them. Repeated exact imports and script installation are supported. Reapplying without `--enable-reviewed` deliberately resets the scoped base task/recipe/reward rows to disabled; include the flag when maintaining an already enabled known-scope installation. If SQL or script installation fails, keep services stopped and inspect/restore the saved database/quest backups before retrying; the multi-file SQL import is not one atomic transaction. The installer never starts/stops services or deploys binaries.

The global-player hook is appended while preserving existing callbacks; the private full global-player script is not shipped. Database backups are private operator data and must not be published.

## Mechanics and validation limits

Gate progression requires the genuine earlier task stage and preserves permanent access after a repeat cycle. Native task events own ordinary kills, handins and progression; only researched feather possession objectives use explicit preloot inventory observations. Wrong-island handins are rejected before consumption. Lost quest-item recovery and duplicate prevention are retained.

Explicit native spawn/actor/model metadata enrolls only the 82 reviewed nests. Target-bound LOS ignores only the nest's matched collider triangles and preserves intervening walls/foreign geometry. Destroyed enrolled lootless nests retain safe stage4 ruins under the original Spawn2 deadline, reject repeated damage/death and preserve single kill/merit callbacks; restored pending ruins do not invent gameplay callbacks. Unbound, foreign, housing and ordinary NPC paths retain their original behavior. Exact original Live server lifecycle is unproved; this is a scoped emulator correction built around shipped client behavior. Crash-before-snapshot/disabled snapshot persistence remains a stated limit.

Offline checks passed nine affected public translation units, linked Map/BVH obstruction tests, assertion-enabled lifecycle contracts and exact twelve-file patch reapplication. The corresponding combined develop server passed a full compile/link and native gameplay checks: six quests with component credit, all seven nest types, late-entry ruins, native respawn deadline/fresh replacement, all feather objectives/handins, item+XP delivery and paired parent earrings retained after fresh login. A full standalone achievement-only link/native rerun was not repeated. Not every quest was natively completed; exact remaining cases are listed in [native status](provenance/native-status.json). Client selection clears on nest death; its local combat toggle still requires attack off. No new opcode or client-toggle fix is claimed. Tests, logs, client assets, raw walkthroughs and private runtime/player/housing data are excluded.
