# Utility source provenance

The authoritative selections and archive SHA256 values are in `utilities-sources.json`. The setup installer downloads those exact commits, verifies source archives, builds Spire and PEQ Editor, and records source commits plus resulting binary/image identities in its persistent installation lock. Public source patches are included under `patches/` for review; installation builds the actual fork commits, without applying an opaque overlay to an unrelated upstream version.

* Spire: [nightstalker6669/spire](https://github.com/nightstalker6669/spire), integration commit `bc6e88f1f84a595cf7fa496302ee644cb6678ce5`, based on upstream EQEmu/spire v4.24.2 (`95ef0be30e4a4b6894b303cf8e6573539d055b8b`). Commits preserve unknown native JSON fields during typed saves, integrate published-project releases and same-origin native websockets, and expose a passive check using the existing native resource ACL for the Docker process adapter.
* PEQ Editor: [nightstalker6669/peqphpeditor](https://github.com/nightstalker6669/peqphpeditor), integration commit `da8c24099ed5081552a8bb48a46375bee9229111`, based on ProjectEQ/peqphpeditor `7a8412e3589babfbd738e2b14a805d246c1e6ce8`. Eleven files cover the reviewed schema 9338 additions, merchant copy behavior and validation, full-width spell IDs, and the existing future-schema warning.

Upstream attribution and source history remain in those repositories. Third-party software retains its original notices. Spire's frontend builds with Node 22; its Go build uses Go 1.25 and the upstream Packr1 generator with the compatible build-only Packr2 v2.8.3 dependency. This tool dependency adjustment does not replace fork application code. Build metadata records exact downloaded sources and compiled outputs; ordinary restart does not rebuild them.

Container-specific process ownership, console transport, verified native release installation, persistent paths and complete backup/restore orchestration live in this setup package. The native inventory supervisor's owned-Zone birth/reaping/recovery implementation is retained. Its optional process tuple and Zone-count argument capacity are adapted to the persistent operator configuration; source/adapter hashes are recorded under `/data/admin/supervisor-provenance.json`.
