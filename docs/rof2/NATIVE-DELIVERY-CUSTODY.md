# Native Deliver hand-in custody

A quest NPC can receive four items that native Deliver has already credited plus an unwanted coin. A script hand-in check then fails exact money equality. Returning the full item bucket would return items whose task progress was already credited. Native delivery tags are on the original trade instances and are lost when CheckHandin clones them.

Capture each offered instance's original quantity and bounded native-delivered quantity before cloning. Keep the published tentative CheckHandin matcher, which commits script consumption only after all requirements accept. Before returning items or retaining a multiquest bucket, cap each remainder to `min(script remainder, original quantity - native delivered quantity)` and remove zero-count entries. This cap is idempotent; an accepted script claim and native delivery do not subtract the same units twice. The original-items vector owns each clone; active entries are aliases. Reconciliation erases only those aliases. After return logging, ordinary reset releases every owner; multiquest reset releases only owners absent from the retained active bucket, so the next hand-in cannot overwrite and lose them. NPC destruction releases any remaining retained owners.

Entries with default original_count0/native_count0 retain their positive script remainder; the native cap runs only when both quantities were captured and native consumption is positive. The required-item constructor has no clone and does not enter this owner bucket; the legacy CLI test structs are separate types. Multiquest copies preserve the captured counters.

Only positive remainders reach PushItemOnCursor. Returned stack charges, return-event charges and the text log describe that remainder; the original hand-in event preserves the offered stack quantity. Charged nonstackable items retain their item charges. Exact coin matching/refunds, non-quest native delivery handling, global ItemInstance cloning, task progress and script APIs are unchanged.

Source review: patch applies with strict whitespace checking to pinned shared-core commit `4d1b0496ed94c861c1bb5e14dbf67117f7c3bae9`. Existing failed-extra-coin, successful-partial-stack, nonstackable-failed-coins and multiquest-retention regression inputs were reused for a source walk; no new test matrix or execution was performed. Untagged failures retain the original quantity; the existing partial success keeps its script remainder. In the reported four-native-items/one-unwanted-coin case, the reconciled item remainder is zero and the existing money path returns the coin. This is a source-level consequence, not a measured native outcome.

Build and runtime validation remain pending. No build, deployment, restart, database write, client action or forced extra-coin test accompanies this source checkpoint. The current quest acceptance run can continue independently. Prior headless matcher results do not validate this new native-tag handling. Arbitrary script-created external item refunds still bypass bucket quantity accounting; this change does not claim general economic exactly-once behavior or crash durability.
